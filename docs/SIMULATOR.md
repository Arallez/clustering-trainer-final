# Модуль `simulator` (Симулятор алгоритмов и Песочница)

В проекте есть две системы для интерактивной работы:
1. **Визуальный симулятор** (`apps.simulator`) — frontend-инструмент для пошаговой визуализации работы алгоритмов кластеризации.
2. **Песочница кода / Sandbox** (`apps.tasks.sandbox`) — backend-движок для безопасного выполнения пользовательского Python-кода (привязан к модулю `tasks`, но концептуально является вычислительной песочницей).

---

## 1. Визуальный симулятор (`apps.simulator`)

Симулятор предоставляет пользователю возможность интерактивно применять алгоритмы кластеризации к двумерным датасетам и наблюдать за процессом (включая построение дендрограмм для иерархических методов).

### Маршруты
| URL | View | Описание |
|---|---|---|
| `/simulator/` | `index` | HTML-страница приложения (Vue 3 + Plotly). |
| `/simulator/run/` | `run_algorithm` | AJAX-выполнение алгоритма на стороне сервера. |
| `/simulator/preset/` | `get_preset` | Загрузка датасета. |
| `/simulator/dendrogram/` | `get_dendrogram` | Получение структуры дерева для агломеративных методов. |

### Связь с другими модулями
*   **С онтологией (`encyclopedia`)**: В `catalog.py` прописан маппинг внутренних ключей симулятора (например, `kmeans`) на концепты онтологии (`Algo_KMeans`).
*   **С профилем и маршрутом**: Запуск симулятора логируется в `SimulatorProgress` и учитывается на странице Learning Path как пройденный шаг.

## 2. Песочница кода (Sandbox)

Песочница используется для безопасного выполнения Python-кода из практических заданий (`Task`). Точка входа: `apps.tasks.sandbox.evaluate_code_submission(user_code, task)`.

### Режимы выполнения
Настраиваются в `config/settings.py`:
*   `SANDBOX_EXECUTOR=docker` — код запускается внутри изолированного контейнера `clustering-sandbox:latest` (без сети, read-only, с лимитами по памяти и процессору).
*   `SANDBOX_EXECUTOR=inprocess` — (Fallback) код выполняется внутри процесса Django, но проходит жесткий статический анализ (проверка `import`, `eval`, `exec`) и ограничивается трассировщиком `sys.settrace` по количеству инструкций.

### Как происходит проверка
1. Песочница применяет статический анализатор безопасности (`is_safe_code`).
2. Находит функцию с именем `task.function_name`.
3. Выполняет её на тестовых данных `task.test_input`.
4. Сравнивает ответ с `task.expected_output` (с учетом погрешности `SANDBOX_COMPARISON_ATOL` для float-значений).
5. Поддерживается множественная проверка через массив `cases` в `test_input`. При первой ошибке проверка прерывается.

Результат возвращается в виде JSON с ключами `success`, `correct` и текстом ошибки (или выводом программы).
