# Модуль `materials` (Учебные материалы)

Модуль `apps.materials` отвечает за хранение и отображение теоретических материалов, а также отслеживание прогресса их изучения пользователями.

## Основные модели

1. **`Material`** — сам учебный материал.
   - Хранит контент в формате Markdown (`content`), заголовок, URL-идентификатор (`slug`) и порядок сортировки (`order`). Поле поддерживает разметку Markdown, сырой HTML и формулы KaTeX; преобразование в HTML выполняется на стороне клиента (`marked.js` + KaTeX).
   - Связан с онтологией через поле `concept` (указывает на `encyclopedia.Concept`).

2. **`MaterialProgress`** — отслеживание активности пользователя.
   - Фиксирует `first_opened_at`, `last_opened_at` и `open_count`.
   - Поле `completed_at` заполняется, когда пользователь вручную нажимает кнопку "Изучено".

## Маршруты и Представления

| URL | View | Описание |
|---|---|---|
| `/materials/` | `materials_list` | Единый список всех материалов (отсортированный по `order`). Авторизованным пользователям показываются отметки "изучено". |
| `/materials/<slug>/` | `material_detail` | Страница просмотра материала. Автоматически обновляет прогресс чтения и позволяет отметить материал как изученный. |

## Интеграция с Адаптивными Рекомендациями

Материалы активно участвуют в построении адаптивного учебного маршрута благодаря связи с `Concept`.

Логика рекомендаций реализована в `apps.encyclopedia`:
- **Основной маршрут** (модули курса): Формируется в `apps.encyclopedia.views`. Материалы рекомендуются в зависимости от текущего изучаемого учебного модуля и недавней активности пользователя.
- **Запасной алгоритм** (Fallback): Вспомогательные функции в `apps.encyclopedia.recommendations` могут рекомендовать материалы по "следующим" концептам или непройденным зависимостям (prerequisites) на основе чистого онтологического графа.

*Важно:* Если у `MaterialProgress` заполнено поле `completed_at`, материал исключается из рекомендаций, чтобы студент не получал уже изученную теорию как следующий шаг.

## Особенности базы данных

Физические таблицы в БД называются `core_material` и `core_materialprogress`, так как исторически модуль был частью `core`. Миграции используют state-only операции, чтобы маппить код `apps.materials` на старые таблицы без потери данных.
