# Модуль `testing` и Функциональное Тестирование Проекта

Этот документ состоит из двух частей:
1. **Пользовательское тестирование (`apps.testing`)** — контур контрольных работ, где преподаватели оценивают студентов.
2. **Системное тестирование (Functional Testing)** — автоматизированные тесты и развертывание самого проекта, необходимые для проверки его работоспособности (важно для диплома).

---

## 1. Пользовательское тестирование (`apps.testing`)

Модуль `apps.testing` предоставляет преподавателям инструменты для проведения контрольных работ. В отличие от адаптивного обучения в `encyclopedia`, где оцениваются знания в целом, здесь оценивается конкретная сдача в рамках группы.

### Основные модели
*   **`StudentGroup`** и **`GroupMembership`**: Учебные группы с доступом по коду (`join_code`).
*   **`Question`**: Банк вопросов преподавателя (открытые вопросы, загрузка файлов), не подлежащих автопроверке.
*   **`Test`**: Контрольная работа, собранная из ручных вопросов (`Question`) и автопроверяемых заданий (`apps.tasks.Task`). Имеет дедлайны (`opens_at`, `closes_at`) и лимиты времени.
*   **`TestAttempt`** и **`StudentAnswer`**: Попытка прохождения студента и его ответы на ручные вопросы. Автопроверяемые задачи привязываются к попытке через `UserTaskAttempt.test_attempt`.

### Рабочий процесс (Workflow)
1.  **Преподаватель** создает группу и рассылает студентам код (`/testing/group/create/`).
2.  **Студент** вступает в группу (`/testing/group/join/`).
3.  **Преподаватель** собирает `Test` из своего банка вопросов и задач из `apps.tasks`.
4.  **Студент** начинает прохождение (`/testing/test/<id>/start/`). Автоматические задачи решаются во встроенном редакторе `tasks`, результаты сразу привязываются к контрольной.
5.  Студент завершает попытку (`submitted_at`).
6.  **Преподаватель** вручную проверяет открытые вопросы и выставляет баллы. Итоговый балл складывается из баллов за автопроверку и ручную проверку (`/testing/attempt/<id>/grade/`).

### Ограничения
*   Модуль `testing` изолирован от прогресса `encyclopedia`. Решенные здесь задачи на данный момент не повышают mastery-прогресс по онтологии.
*   Доступна только одна уникальная попытка на пользователя для конкретного теста.

## 2. Автоматизированные тесты и развертывание

Для диплома и обеспечения надежности проекта реализовано автоматизированное тестирование программного кода.

### Запуск окружения
Проект разворачивается через Docker Compose с использованием профиля `sandbox` (web, db, sandbox-контейнер). Ошибка применения миграций блокирует запуск `web` для защиты от неконсистентных данных.

```powershell
docker compose --profile sandbox up --build -d
```

### Автотесты Django
В проекте реализован набор автоматизированных проверок, покрывающий основные архитектурные компоненты. Запуск:

```powershell
.\venv\Scripts\python.exe manage.py test apps.tasks.tests apps.simulator.tests apps.encyclopedia.tests apps.testing.tests --keepdb
```

**Что проверяют тесты:**
*   `apps.tasks.tests`: Работа песочницы, фильтрация AST-дерева, проверка численных результатов с погрешностью (ATOL).
*   `apps.simulator.tests`: Генерация датасетов, расчет K-Means, построение дендрограмм.
*   `apps.encyclopedia.tests`: Порог освоения (70%), блокировка задач, профиль поиска научных статей и отсечение двусмысленных публикаций.
*   `apps.testing.tests`: Полный workflow контрольной работы (группа -> вступление -> прохождение -> оценка).

### Ручное Функциональное Тестирование
Для демонстрации работы проекта рекомендуется провести ручную верификацию:
- Вход в личный кабинет и отслеживание "Пути обучения" (`Learning Path`).
- Открытие визуального симулятора кластеризации и применение алгоритмов.
- Запуск Python-кода с преднамеренно опасными импортами (для проверки блокировки).
- Полный цикл от лица преподавателя: создание группы, теста, прохождение теста студентом, ручная оценка.
