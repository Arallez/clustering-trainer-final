# Модуль `tasks` (Задания и тесты)

Модуль `apps.tasks` отвечает за учебные задания (практика кода и quiz-тесты), обработку попыток решения и автоматическую проверку.

## Основные модели

1. **`Task`** — универсальная модель задания.
   - Поддерживает два типа (`task_type`): `code` (написание скрипта) и `choice` (quiz).
   - Хранит исходный код, эталонное решение (`solution_code`), тестовые данные (`test_input`) и ожидаемый результат (`expected_output`).
   - Связано с онтологией через поля `concept` (главное проверяемое понятие) и `related_concepts` (дополнительные темы для диагностики ошибок).

2. **`TaskTag`** — теги/категории для группировки заданий.

3. **`UserTaskAttempt`** — история попыток пользователя (код, успешность, текст ошибки). Связана с `test_attempt`, если задание решалось в рамках тестирования (`apps.testing`).

## Маршруты и Представления

| URL | View | Описание |
|---|---|---|
| `/tasks/` | `task_list` | Список всех заданий с цветовой индикацией решенных задач. |
| `/tasks/challenge/<slug>/` | `challenge_detail` | Интерфейс решения задачи (подключает Vue-компонент редактора кода или выбор ответа). |
| `/tasks/api/check-solution/` | `check_solution` | AJAX-эндпоинт для отправки кода/ответов на проверку. |

## Как работает проверка решений

Функция `check_solution()` обрабатывает два сценария:

### 1. Quiz-задачи (`choice`)
Бекенд сравнивает выбранные варианты с `expected_output` (с поддержкой множественного выбора) и возвращает статус по каждому пункту.

### 2. Кодовые задачи (`code`)
Бекенд передает пользовательский код в песочницу (Sandbox).
*   **Где выполняется код**: Выполнение изолируется (Docker-контейнер или in-process Django песочница с трассировщиком `sys.settrace`). Механизм песочницы концептуально задокументирован в **`SIMULATOR.md`**.
*   **Сравнение**: Песочница находит функцию `task.function_name`, передает ей аргументы из `task.test_input` и сверяет результат с эталоном. Если входные данные содержат массив `cases`, функция вызывается несколько раз для проверки пограничных случаев.
*   **Ошибки**: Если решение неверное, в ответ добавляется блок `remediation` с перечислением понятий и материалов, которые стоит повторить.

## Связь с Адаптивным Маршрутом (Онтологией)

Поле `Task.concept` включает задачу в цикл адаптивного обучения (`apps.encyclopedia`):
1. **Расчет прогресса (Mastery)**: Студент считается освоившим концепт, если он корректно решил ≥70% задач, привязанных к этому главному концепту.
2. **Доступность**: Пока студент не изучит требуемые базовые концепты, задание может отображаться с пометкой о недостающих темах. Логика доступности (`is_task_available`) реализована в `apps.encyclopedia.recommendations`.
3. **Рекомендации**: Задания подбираются пользователю в зависимости от его текущего учебного модуля во `views.py` энциклопедии.

## Особенности базы данных
Исторически модели `Task` и попытки находились в модуле `apps.simulator`, поэтому физические таблицы в БД сохранили префикс `simulator_` (`simulator_task`, `simulator_usertaskattempt`). Миграции корректно сопоставляют код из `apps.tasks` со старыми таблицами.
