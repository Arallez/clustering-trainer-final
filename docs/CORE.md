# Модуль `core` (Базовый контур и профили)

Приложение `apps.core` не содержит «всю бизнес-логику проекта», а выполняет роль общего входа в систему и управления аккаунтами пользователей.

## За что отвечает модуль

- Главная страница (`/`);
- Регистрация и аутентификация (`/register/`, `/login/`, `/logout/`);
- Профиль пользователя (`/profile/`);
- Перенаправление в адаптивный учебный маршрут.

Учебные материалы, тестирование и база знаний вынесены в отдельные приложения (`materials`, `testing`, `encyclopedia`).

## Пользователи и профили

В проекте есть два уровня пользовательских сущностей:
1. Стандартный `django.contrib.auth.models.User`.
2. Прикладные профили и роли.

### `UserProfile`
Определён в `apps.core.models` (поля `experience_points`, `current_level`). 
Ключевая аналитика строится не на полях модели профиля, а на агрегации активности (решённые задания, история попыток, прогресс по онтологии).

### `TeacherProfile`
Определён в `apps.testing.models`. Это отдельная модель-флаг, которая делает пользователя преподавателем. В коде `core` проверка роли выполняется так: `hasattr(user, 'teacher_profile')`.

## Представления и маршруты

| URL | View | Описание |
|---|---|---|
| `/` | `home` | Входная навигационная точка. Нет сложной вычислительной логики. |
| `/register/` | `register` | Создает `User`, отправляет email с использованием `console.EmailBackend` по умолчанию, перенаправляет на `/login/`. |
| `/login/` | `AccountLoginView` | Встроенный LoginView. При успехе перенаправляет на `/profile/`. |
| `/logout/` | `AccountLogoutView` | Выход. Возвращает на главную страницу. |
| `/profile/` | `profile` | Личный кабинет с аналитикой. |

### Как работает страница профиля
Представление `profile` (в `apps.core.views`) собирает следующую информацию:
1. **Общая статистика**: Всего заданий, уникально решенных, процент прохождения (основано на `UserTaskAttempt`).
2. **Последние попытки**.
3. **Рекомендации**: Вызывает `get_recommended_tasks` и `get_recommended_materials` из `apps.encyclopedia.recommendations`. *(Примечание: для профиля эти функции служат запасным/базовым механизмом рекомендаций, в то время как основная адаптивная логика маршрутов живет в `encyclopedia.views`)*.
4. **Прогресс по базе знаний**: через `get_user_progress`.
5. **Изученные материалы**: счетчики `total_materials` и `completed_materials_count`.
6. **Роль**: является ли юзер преподавателем.
