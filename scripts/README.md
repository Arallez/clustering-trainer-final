# Скрипты

Каталог `scripts/` содержит в основном разовые и исторические утилиты. Это не основной путь сопровождения проекта: рабочие операции сейчас выполняются через Django management commands и стандартные команды `manage.py`.

Запускать скрипты нужно из корня репозитория:

```bash
python scripts/<имя_скрипта>.py
```

## Что лежит в каталоге

### `fix_materials.py`

Старый скрипт ручного обновления одного из теоретических материалов. Полезен только как пример одноразовой миграции контента.

### `fix_migrations.py`

Историческая утилита для ручной корректировки состояния миграций.

Использовать только если вы точно понимаете, зачем нужно исправлять таблицу `django_migrations`.

### `fix_migrations.sql`

SQL-вариант того же сценария. Актуален только для ручного восстановления старых локальных БД.

### `init_materials.py`

Старый скрипт первоначального наполнения материалов. Сейчас вместо него обычно используются:

- `python manage.py loaddata fixtures/datadump.json`;
- редактирование материалов через `/admin/`;
- management command `load_test_course`, если нужно пересобрать учебный курс.

### `init_tasks.py`

Старый скрипт для начального создания задач. Основная логика наполнения проекта теперь живет либо в дампе `fixtures/datadump.json`, либо в management commands внутри приложений.

### `make_dump.py`

Утилита для создания переносимого дампа данных проекта.

Обычно она нужна после изменения учебного наполнения:

- материалов;
- понятий и связей онтологии;
- задач;
- тестовых данных курса.

## Что использовать вместо старых скриптов

Для актуального проекта предпочтительнее:

- `python manage.py migrate`;
- `python manage.py loaddata fixtures/datadump.json`;
- `python manage.py sync_ontology`;
- `python manage.py load_test_course`;
- работа через `/admin/`.

## Когда имеет смысл трогать `scripts/`

- если нужно восстановить старое локальное состояние БД;
- если вы переносите данные из ранней версии проекта;
- если нужно понять историю развития структуры материалов и задач;
- если нужно вручную собрать дамп через `make_dump.py`.

Во всех остальных случаях лучше не строить новые процессы вокруг этих файлов, а переносить нужную логику в:

- management commands;
- миграции;
- админ-панель;
- сервисные функции приложений.
